# 轻量动画 Agent V2 设计草案

## 结论与定位

新版对所有动画采用同一条流程：一次简短故事规划、一次生成所有关键帧，再逐 gap one-shot，最后校验和渲染。帧数改变时间分配和批次预算，不触发另一套生成架构。用户提出细节修改时，只重新生成受影响的姿态和区间。

Whole one-shot 已经是有竞争力的生成器，保留为独立实验对照和消融，不作为新版按动画长度切换的生产分支。论文可以统一描述故事规划、稀疏关键姿态联合生成、端点约束的区间生成这三个阶段。

核心流程已实现为独立原型（`cli.py`），首个实测为 40 帧 2D 报警喷淋任务；gap 截断后自动拆批已实现，关键帧拆批和交互编辑仍是后续设计。默认显式设置 max_tokens=393216（384K），thinking 保持 high；预算包含思考和最终输出，不要求用完。质量与速度收益待实测，不把“agent 步骤更多”当作质量更高的依据，也不承诺删步骤后自动更快。现有版本已备份，V2 可独立试验。

## 现有代码实际在做什么

常用 Complex 实验路径是：

```text
简短请求 → 一次扩写/plan → 各关键帧 one-shot → 各 gap one-shot → 校验/渲染
```

`experiments/baseline_advantage_12/run_local.py` 的 3D 命令显式使用 `--key-mode oneshot`；2D 的相应模式也使用 one-shot。源码仍保留 incremental、逐帧重绘和可选 reflection 等历史入口，增加阅读与依赖成本，但它们不是当前常用实验路径每次都会执行的步骤。

现有优点应保留：完整片长的节奏规划；稳定身份和固定场景；接触、释放、结果的因果顺序；各 gap 一次生成；对上一姿态和下一事件的上下文；可直接打开的 GIF 和 contact sheet。

值得精简的具体位置：

| 当前情况 | V2 建议 | 理由 |
|---|---|---|
| `parts/keys/gaps` 分别描述形状、动作、时长，并多处重复规则 | 全局简短说明 + 一张事件时间表 | 保留语义，减少字段协调与格式修复 |
| 2D/3D 分开的 planner、drawer、增量编辑与实验包装器 | 一套控制流，两个路径格式/渲染适配器 | 把维度差异留在几何协议里 |
| 每个关键帧单独生成，再填区间 | 优先把全部关键帧合为一次生成 | 减少调用，同时保留已验证的端点约束 |
| Gap 输入可能同时带首次、上一、FROM、TO、下一关键帧几何 | 两端几何 + 去重身份参考 + 简短相邻事件；必要时补邻帧 | 减少重复，同时保留目标姿态和运动方向信息 |
| 所有 canonical strokes 每帧必须出现一次 | 稳定 ID，允许对象按故事出现和消失 | 消失后保留同一笔画与故事目标可能冲突 |
| 固定颜色、笔宽反复要求模型填写 | 渲染器统一样式默认值 | 可以由程序保证的格式不耗生成长度 |
| 默认生成全部 3D 四视图 | 默认 perspective；诊断时开四视图 | 与实际展示用途一致 |
| 传输、JSON 修复、key attempt、suite retry 分层 | 统一失败分类与重试预算 | 避免一次失败在多层重复付费与等待 |

关键帧形状约束有价值。不能未经验证就宣称删掉端点锚定不会降低质量，尤其是物理接触、跨段交接和角色比例。

| 游乐场救球 | 2D / 60 | 46.52s | 405.29s | 1058.07s | 25.16min | 70.1% |
| 游乐场救球 | 3D / 60 | 59.92s | 375.56s | 1424.39s | 31.00min | 76.6% |

数据源和完整数值见 `CURRENT_AUDIT.json`。阶段时间包括对应阶段的生成与处理，不能直接等同于模型推理时间；个别重试也可能包含其中。

当前 planner system prompt：2D 10,252 字符、3D 11,026 字符；2D 的组合绘画规则 `DRAWER_ORIENTATION` 为 8,207 字符。这些是实际字符串字符数，不是 tokenizer token 数，也不是把整个任务库误算为发送给模型的提示词。

所以精简脚本与 JSON 会改善维护、输入成本和可靠性，但大部分时间来自输出大量逐帧路径。新版应同时减少重复描述、合理分段、控制无意义路径细节；减少调用次数不等于同等倍数的加速。

## 向 PDoomVideo 借什么

| PDoom 文件 | 借鉴方式 |
|---|---|
| `STORYBOARD.md` | 每段有明确事件、时长和交接；内容充实且观众能看懂 |
| `ANIMATION_GUIDE.md` | 一份共享规范，统一身份、表现形式和检查重点 |
| `src/clawd.js` | 共享角色定义；我们的第一步用稳定 ID 和形状参考实现 |
| `src/timeline.js` | 每段有明确时间范围、入口与出口 |
| `renderSheet` / `render.mjs` | 全局 contact sheet 与边界连续帧检查 |

PDoom 的 `fn(t, lt, dur)` 是模型写出的连续时间绘画程序。同一套角色代码会自动保持身份；我们目前让模型输出每一帧的 Path2D/Path3D，没有这个自动保证。因此不能把其长片效率直接套到我们的 JSON 生成模式上。

它的 Markdown 是创作说明与协作规范，具体时间表和运行逻辑仍在代码里。Markdown 适合阅读、讨论和局部编辑，也允许自然语言表达“这一段观众应看懂什么”；JSON 适合程序执行和校验。格式本身不会自动提高模型推理能力。

## 统一生成流程与编辑接口

建议只有一个入口：

```text
generate(prompt, dimension, frames, frame_ms)
edit(run, instruction, affected_range=None)
```

所有长度都执行相同的规划、关键帧生成和区间生成，不设置短/长阈值或自动 Whole 路由。2D/3D 也共用控制流程，只切换路径协议与渲染适配器。编辑是既有结果上的操作，不是另一种初次生成架构。

### 一次规划 + 全部 Keys One-shot + Gap One-shot

```text
简短请求 → Storyboard → 全部 Keys 一次生成 → 各 Gap 一次生成 → 拼接/渲染
```

Planner 一轮输出简短故事和事件时间表。每段末帧对应明确出口姿态，第一帧加这些出口帧构成稀疏关键帧序列。必须发生接触/释放等关键变化时，给该事件安排独立 beat，而不是让模型猜它是否发生。

Key drawer 在一份响应里返回所有指定关键帧，包括第一帧。看到的是整个有序故事及所有关键姿态要求；统一对象 ID、比例、场景和道具尺寸，不单独给每个 key 再调用模型。输出仍是普通的 `frames` 数组，只是帧号稀疏；不生成中间帧。

程序逐 key 校验并登记固定背景/身份参考。Gap generator 继续使用两端已接受几何、少量邻近运动信息和首次身份参考，一轮生成该区间中间帧。这保留了当前方法的强项，主要改变调用编排和冗余输入。关键帧批次结构失败时只修该批次；个别姿态语义失败时只修相关姿态，再生成其相邻 gap。

若关键帧数量或几何复杂度超过一份输出预算，将 keys 分成少量批次，后续批次带首批身份参考及前一 key。不能为了“必须一轮”重新引入长 Whole 的输出长度问题。关键帧通常较少，因此优先验证整批生成。

120 帧、12 个 key 的名义调用量从 `1 plan + 12 keys + 11 gaps = 24` 降为 `1 plan + 1 key batch + 11 gaps = 13`；不含修复与传输重试。节省的是 11 次关键帧调用，不是少画 11 个关键帧。Gap 仍占主要耗时，速度收益需要实测。

### 长度变化只影响同一流程中的规模

关键帧数量由接触、释放、状态变化和明显姿态变化决定，不按总帧数机械增加，不强迫简单动作使用很多 key。一个短动作也执行相同阶段，只需要较少姿态和区间；一个长故事使用较多事件，并按实际播放时长分配各区间帧数。

某个 gap 的输出超出预算时，将它切成连续小批次，沿用相同的区间生成器和固定最终目标姿态。后续批次复用前批末帧，并带末两帧的运动信息；请求帧范围不重叠，不重新生成已接受帧。批次切分只管理输出预算，不另设方法或按片长换生成器。

保持关键帧和区间之间的边界约束；用相邻事件和必要的邻近姿态提供运动方向，避免每到 key 都停顿。批量 key 可以减少独立调用，但不能自动保证姿态、身份或物理正确。

对象首次出现时登记稳定 ID；消失时不再输出其可见笔画，后续重现复用 ID。场景中始终存在的背景由程序复用。对象可见性规则适用于全部动画，不因片长改变。

### 细节/交互：只修受影响片段

示例：“左边的人改成女孩”“开花必须在浇水结束后”“喷水要明显连到火焰”。

Agent 将反馈转为明确的视觉目标，确定对象与时间范围，重生成受影响区间，并检查两端拼接。角色身份修改通常覆盖整个片段中该角色出现的范围，不应假装只改某个 key 就自动影响所有帧。

如果“女孩”需要头发等识别信息，新版应让用户明确修改高于默认无头发风格，而不是被旧硬规则拒绝。修改保存新 revision，原结果可回看。

## 精简 Planner：一份 Markdown，一张时间表

所有任务使用同一个简短 planner。输出仅包含：

- `Action`：首轮扩写，短而完整的有序故事。
- `Notes`：固定身份、布局，以及少数易误解的视觉要求。
- `Beats` 表：`frames | event | exit`。事件包括进入状态、正在发生的动作和关键可读信息；出口写下一段必须接住的状态。

程序读取约定的三个区块，时间范围仅接受 `start-end`；检查整数、连续覆盖、顺序和总帧数。不要解析任意 Markdown 语言，也不要让模型重复返回 JSON 和 Markdown 两份计划。程序从这张表派生关键帧索引和小型 schedule/manifest；路径数据仍使用 JSON。

删掉独立 `parts[].how/notes`、`keys[].notes`、`gaps[].why/ease` 的多处重复。身份/布局与动作叙事各写一次；缓入缓出、接触后回弹等自然语言写进事件即可。稳定笔画 ID 在一次关键帧绘画时建立，不要求 planner 为每个细笔画先设计一遍。

参见 `prompts/PLANNER.md` 和 `examples/sprinkler_storyboard.md`。MD 的目的在于简化表达，不是把结构约束藏进更难解析的文本。

## 提示词：保留关键原则，按阶段分工

全局规范只保留：看得懂、身份稳定、先后顺序正确、接触真实、节奏合适、跨段不断、对象出现/消失合理。固定风格由渲染器和短几何规范负责。

- Planner 负责事件顺序、真实播放时长、舞台布局和观众应看懂的内容；不设计曲线和逐笔画解剖。
- Drawer 负责具体姿态、可辨认轮廓、关节连接和路径语法；不重复整个规划任务。
- Edit/repair 只写发现的问题、目标范围和相关边界，避免每次重复全套规划要求。

人/动物等专项规则按实际题材加载，不能为了减少字符把已经验证有用的圆头、动物识别特征和关节连接全删掉。原提示词可能过长，但其历史上解决过的失败点值得用实测筛选。

## 检查与输出：有边界的质量控制

始终执行廉价结构检查：JSON/路径可解析、坐标有限、帧号/数量正确、单帧 ID 唯一、稳定对象 ID 不漂移、固定背景一致。越界等需要单独报告；不能把所有不合理坐标强行 clamp 后当成“通过”。

语义质量不由 schema 保证。所有动画输出一张全局 contact sheet 和边界附近的连续帧条；默认由人检查。若启用视觉 reviewer，必须配置能实际看图的模型，最多一轮全局 review 加受影响段的有限修复。文本 DS 不能仅凭 JSON 检查就被描述为已经看过动画。

非重叠段的接触、因果和边界是主要风险。程序可用同 ID 的位置/包围盒变化做异常提示，但不能用平均中心位移假装证明物理正确，也不能自动平滑掉碰撞瞬间。

默认输出：`request.json`、`storyboard.md`、`animation.json`、`clip.gif`、`contact_sheet.jpg`、`metrics.json`。调试模式才展开逐帧文件、四视图和原始响应。断点恢复使用已成功段的小型 checkpoint，而不是每一笔建立 revision 目录。

统一记录总墙钟、plan/key batch/各 gap/repair/validate/render 阶段耗时；每次实际请求的耗时、尝试次数、usage、reasoning usage（若提供）、finish_reason、错误分类。失败结果也留记录，避免只统计成功速度。

## 实现边界与验证顺序

建议核心仅为 `cli.py`、`pipeline.py`、`provider.py`、`storyboard.py`、`scene.py`、`render.py` 和少量 prompt 文件。沿用现有 Path2D/Path3D parser/schema/renderer；不要为了“新版”重写稳定几何代码。Provider 保留配置化入口，但统一模型与 thinking 参数的翻译。

先测以下小批：

| 测试 | 帧数 | 观察点 |
|---|---:|---|
| 接球再投篮 | 24 | 同一架构在较少帧下的流畅度、接触和额外成本 |
| 报警器触发喷淋灭火 | 60 | 先触发后喷水、喷水接触后灭火；跨段接触与事件可辨认 |
| 城堡吊桥送货 | 120 | 长时间身份稳定、放桥后通行、段边界不断或瞬移 |

每题测试 2D/3D，对比已有 Complex 逐 key+gap、新 V2 批量 key+gap、Whole。V2 在 24/60/120 帧均采用同一流程和同一组生成规则，避免为某个片长单独调架构。公平实验采用“共享首轮扩写”输入：所有生成器收到相同的 Action/Notes；Complex/V2 额外接收其架构所需的时间表。Whole 是一次输出全部帧的对照，不是 V2 的短动画分支。

记录完成率、实际生成帧数、可见因果顺序、对象身份、接触、边界跳变、人看图能否认出动作、总耗时、输出 token 与修复次数。失败和修复也算入成本。先验证批量 key 是否保持现有 key+gap 质量并节省时间，再考虑把 V2 设为默认。

若批量 key 版本某些关键姿态出错，先修这些姿态并重新生成相邻 gap；若主要耗时仍是输出长度，就不能只靠继续压缩 planner 来解决。

## 单独的后续研究：生成动画程序

更接近 PDoom 的路线是输出一次角色/轨迹/动作程序，由程序计算全部帧。它能避免把每帧几何重复输出，可能更适合很长动画，但需要新的执行协议、角色资产、运动控制与评估；也会改变我们当前方法及实验可比性。它值得作为独立研究方向，不混入第一次轻量重构。

## 已实现的 gap 并发

关键帧整批完成后默认并发绘制 gaps（最多六个，可配置），两维共用同一实现。每段共享故事、身份参考、固定背景和已接受的前后关键帧，并带上一及下一关键帧的时间索引；不等待上一段中间帧。串行选项使用同样上下文以便对照。gap 内的截断恢复按小批次顺序进行。

关键帧和故事提供因果边界，但并发后的跨段速度衔接尚未做视觉验证，不能声称严格连续。计时分别记录总墙钟、gap 墙钟及每请求耗时；checkpoint 和 metrics 文件写入受锁保护。更换上下文会使旧 gap 的缓存失效，已有旧动画不会自动改写，重测使用新输出目录。

风格迁移：参考 baseline_snapshot_20260927 中旧版 2D/3D prompts.py 的 DRAWER_ORIENTATION、ANIMAL_DRAWING、INK_STYLE 与 VISUAL_COMMUNICATION，提炼为圆头单线火柴人、可爱简洁的动物轮廓和醒目物种特征、统一黑线与易识别道具。具体偏好写入共享绘画指南，planner 只保留简短风格描述；不恢复旧版 parts 表、尺寸硬比例和复杂检查脚本。新风格实验单独保存。

## 真实 3D 空间约束

3D planner、key batch 和 gap 共用 `prompts/SPATIAL_3D.md`。实体要有合理深度结构，不能用平面轮廓加透视相机冒充体积；球体采用不同平面的空间轮廓，箱体连接前后边，竖直桶口在水平 x-y 平面展开。合法平面物体和火柴人中心线不强制加厚。规则保持线稿简洁，不增加 planner 字段、零件清单或几何体积检查。

当前批次已按要求暂停，提示词修订尚未经真实模型重测，不能宣称已解决伪 3D。原因对照与实际几何证据见 `SPATIAL_3D_AUDIT_ZH.md`。
